### Concrete Findings

#### 1. State Bugs
1. **Cross-Tab State Collision (`text` and `file`)**:
   - `text` and `file` are shared between Tab 0 (AI prompt + image file) and Tab 2 (TSV paste + spreadsheet file). Switching tabs preserves inputs across completely different formats, allowing an image file or AI text to leak into the spreadsheet parser and vice versa.
2. **Stale `input.value` on File Removal**:
   - In Tab 0, `setFile(null)` clears React state but does not reset `input.current.value = ""`. Selecting the same file again fails to trigger `onChange`.
3. **No File Reset in Tab 2**:
   - Tab 2 displays `{file && <p>{file.name}</p>}` but provides no way to remove the file once selected or dropped.
4. **Stale `preview` State on Text Edit**:
   - In Tab 2, editing `text` does not reset `preview`, keeping outdated or broken preview rows rendered even if `text` is cleared.

---

#### 2. Validation Bugs
1. **Pasted Text Preview Blocked by File State in Tab 2**:
   - In Tab 2, `if (file)` check runs before previewing `text`. If a file is selected (or leaked from Tab 0), valid pasted text can never be previewed.
2. **Unvalidated Drag-and-Drop in Tab 2**:
   - `onDrop` sets `file` directly without verifying file size (`<= 2MB`) or extension (`.xlsx`, `.csv`), and fails to reset previous errors (`setError("")`).
3. **Error State Never Cleared on Input**:
   - In Tab 1, neither `term` nor `meaning` input `onChange` resets `error`, leaving validation or "Tự điền" errors stuck on screen while typing.
4. **TSV Parsing Ignores CRLF (`\r\n`) and Missing Columns**:
   - Splitting by `\n` retains `\r` on Windows clipboard copies (Excel/Sheets). Incomplete lines render fewer `<td>` cells than the 2-column `<th>` header.

---

#### 3. Keyboard Bugs
1. **Missing `type="button"` on Tab Buttons and Actions**:
   - All tab buttons `<button role="tab">` and inner action buttons (e.g., `＋ Thêm ảnh`, quick presets, file picker) omit `type="button"`. If wrapped in or placed near a `<form>`, pressing Enter triggers unintentional form submissions.
2. **Hardcoded Tab Indices in Navigation**:
   - `keyboard()` uses magic numbers `3` and `2` (`(i + 1) % 3`, `(i + 2) % 3`, `End -> 2`) rather than `names.length`.

---

#### 4. ARIA & Accessibility Bugs
1. **Missing Error Association (`aria-invalid`, `aria-describedby`)**:
   - Tab 1 inputs lack `aria-invalid` and `aria-describedby={`${id}-error`}` when validation fails. Screen readers navigating the form receive no feedback that fields are invalid.
2. **`aria-expanded` Without `aria-controls`**:
   - The "Tạo danh sách mới" button defines `aria-expanded={list}` but has no `aria-controls` linking to the conditionally rendered field.
3. **Missing `role="tab"` Button Type**:
   - `<button role="tab">` elements lack explicit `type="button"`.

---
